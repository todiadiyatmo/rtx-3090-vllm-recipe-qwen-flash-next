## Build and audit

From the repository root:

```bash
docker build -t local/qwen38-flash-next:e962733e-ampere-pp recipe/patch
```

`overlay/` contains 22 Python source files, copied byte-for-byte from the tested
development overlay; generated bytecode is excluded. `SHA256SUMS` records their
hashes and the unified diff's hash. Check them from this directory:

```bash
sha256sum -c SHA256SUMS
```

The Dockerfile copies the overlay; it does **not** run the unified patch.
`nightly-e962733e-flashnext-pp.patch` is the audit/rebase alternative. To use that
alternative, start with a clean source tree at the exact base commit and run
`patch --dry-run -p1 < /path/to/nightly-e962733e-flashnext-pp.patch` from its root
before applying it. Do not apply it on top of the overlay.

### Rebase pitfalls

- Do not bind-mount the older `ple_layer.albucino-fp8ple.py`: it predates fused
  PLE and overwrites the implementation this build depends on.
- QSA warmup calls the kernel positionally. Update it together with quantization
  arguments and Ampere dispatch, not just the steady-state kernel.
- Preserve `@triton.jit` decorators. A missing decorator previously passed Python
  syntax/import checks but failed at GPU compilation.
- The raw PLE offload PR rejected PP. Keep the placement-aware worker checks and
  the graph `signal_dummy_outputs` synchronization.
- One old offload padded-buffer hunk was intentionally omitted: fused PLE now
  allocates that CPU buffer to the actual request shape.
